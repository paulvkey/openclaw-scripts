# 芯片规格文档生成器

生成带有嵌入式 SVG 图表的专业芯片设计规格文档（.docx）。涵盖架构规格、详细设计规格以及芯片模块的验证计划。

## 使用场景

- 用户要求创建芯片/模块设计规格
- 用户要求架构文档、详细设计文档或验证计划
- 用户需要框图、FSM 状态转移图或时序波形图
- 用户需要 UVM 测试平台结构或验证计划文档

# 前置流程：材料收集（必须第一步执行）

在绘制任何图表或编写任何章节之前，先收集所有可用材料：

## 必需文档

| 文档 | 需提取内容 | 缺失时 |
|---|---|---|
| 功能规格 (.docx/.md) | 操作流程、触发条件、状态描述、时间约束 | → 提示用户提供 |
| 寄存器文件 (.xls/.xlsx) | 寄存器地址、位域、默认值、访问类型 | → 提示用户提供 |
| 接口描述 (.xls/.xlsx) | 信号名、方向、位宽、默认值、时钟域 | → 提示用户提供 |
| 已有参考图 (.pdf/.png) | 时序图风格、画法、信号标注方式 | → 如果有则直接使用 |

**关键**：如果缺少任何这些文件，停止并提示用户。不要猜测信号位宽、默认值或时序关系。

## 参数提取检查清单

开始生成任何 SVG 或文档之前，先确认：

```
□ 所有信号名称、方向、位宽（来自接口文档）
□ 所有信号默认值（来自接口文档）
□ 所有寄存器地址、位域、复位值（来自寄存器文件）
□ 所有时序约束：setup/hold、超时、脉冲宽度（来自规格文档）
□ 所有 FSM 状态和转移条件（来自规格文档）
□ 所有操作序列（来自规格文档：软件流程、硬件流程）
```

# 时序图规范

## 前置条件：事件表（必须执行——不可跳过）

在写任何一行 SVG 元素之前，为每个时序场景构建一个 T0..Tn 事件表。列出每个信号在每个时间标记处的状态。

### 事件表模板

```
场景：<名称>（<软件/硬件流程>）

T0：<触发条件>
    信号_A = <默认值> → <新值>     # 原因 / 来源
    信号_B = <默认值>                # 保持默认
    FSM：<状态_A> → <状态_B>

T1：<条件>
    信号_A = <值>
    信号_B = <默认> → <活跃>        # 原因

T2-Tn：...
```

**事件表关键规则**：
1. 每个信号在每个 T 标记处都必须列出状态（即使不变——写"保持 <值>"）
2. 默认值必须来自接口/寄存器文档——绝不猜测
3. 中间状态必须展示——不要跳过或合并状态
4. 如果不确定某个跳变时刻，标记出来并询问用户

### 示例（上电初始化，软件流程）

```
T0：SW 写 init_start=1（W1C，寄存器 trim_op_ctrl[4]）
    clk              = 持续翻转
    init_start       = 0 → 1（W1C 脉冲，1 个周期后硬件自清）
    spine_reset_n[0] = 0（保持；默认值 0x0，低有效）
    tsv_tm[428:1]    = NULL（默认值 0x0，SW 已预先配置）
    init_done_flag   = 0（保持；RO 寄存器，默认值 0x0）
    FSM 状态          = IDLE → INIT_RESET

T1：计数器启动；tsv_tm 驱动为有效值
    init_start       = 1 → 0（硬件自清 W1C 位）
    spine_reset_n[0] = 0（保持；计数器计 init_spine_reset_time）
    tsv_tm[428:1]    = NULL → VALID（SW 预配置值）
    init_done_flag   = 0（保持）

T2：Setup 检查点（tsv_tm 在 spine_reset_n 上升沿前稳定）
    spine_reset_n[0] = 0（保持；active，计数器接近结束）
    tsv_tm[428:1]    = VALID（保持；上升沿前 setup 时间 ≥1ns）

T3：计数器到期；spine_reset_n 释放
    spine_reset_n[0] = 0 → 1（释放；DRAM 在上升沿锁存 TSV_TM）
    tsv_tm[428:1]    = VALID → NULL（上升沿后 hold ≥3ns）

T4：初始化完成
    init_done_flag   = 0 → 1（硬件置位）
    FSM 状态          = INIT_RESET → INIT_WAIT

T5：DRAM 响应
    dump_ready[0]    = 0 → 1（来自 DRAM，异步；时间可变）
```

## 信号分类与画法规则

### 类型 A：单比特控制信号（默认=0，脉冲触发）

示例：`init_start`、`tm_redump_active`、`stopwatch_period_active`

画法：
- **单条连续 `<polyline>`**，从波形区左边界到右边界
- LOW 状态：y = 中心_y + 10
- HIGH 状态：y = 中心_y - 10
- 模式：`...LOW... → HIGH（脉冲）→ LOW...`

```xml
<!-- init_start：中心=196，LOW=206，HIGH=186 -->
<polyline points="220,206 260,206 260,186 300,186 300,206 870,206"
     stroke="#3b82f6" stroke-width="2" fill="none"/>
```

### 类型 B：单比特状态信号（默认=0，升为 1）

示例：`init_done_flag`、`dump_ready[0]`、`ringo_period_ready`

画法：
- **单条连续 `<polyline>`**，从波形区左边界到右边界
- LOW → HIGH 跳变
- 模式：`...LOW... → HIGH...`

```xml
<!-- init_done_flag：中心=490，LOW=500，HIGH=480 -->
<polyline points="220,500 650,500 650,480 870,480"
     stroke="#10b981" stroke-width="2" fill="none"/>
```

### 类型 C：单比特状态信号（默认=1，操作期间变 0，恢复为 1）

示例：`active_ready`、`spine_resetn_active_ready`、`tm_redump_active_ready`

画法：
- **单条连续 `<polyline>`**
- 模式：`...HIGH(就绪)... → LOW(忙碌)... → HIGH(完成)...`

```xml
<!-- active_ready：中心=526，LOW(忙碌)=536，HIGH(就绪)=516 -->
<polyline points="220,516 270,516 270,536 565,536 570,536 570,516 870,516"
     stroke="#10b981" stroke-width="2" fill="none"/>
```

### 类型 D：总线信号（>1 bit）

示例：`tsv_tm[428:1]`、`osc_tm_res[11:0]`

画法：
- **填充色带**：用 `<rect>` 或 `<polygon>` 加 fill
- 过渡区（NULL/未知）：**灰色填充** `#e2e8f0`，从过渡区起点连续填满
- 有效区（已知数据）：**黄色填充** `#fef3c7`，标注值居中
- **不画交叉斜线**——过渡区绝不画"X"标记或对角线
- **不画边缘细线**——灰色区连续延伸，不在色带边缘加单独 `<polyline>`

```xml
<!-- 总线：起点全灰 → 黄色有效色带 → 全灰 -->
<!-- 灰色过渡区（NULL） -->
<rect x="220" y="358" width="190" height="48" fill="#e2e8f0" stroke="none"/>
<!-- 黄色有效区带标签 -->
<rect x="410" y="358" width="250" height="48" fill="#fef3c7" stroke="#fcd34d" stroke-width="1.5"/>
<text x="535" y="386" text-anchor="middle" font-size="10" font-weight="700" fill="#92400e">tsv_tm_valid</text>
<!-- 有效区之后的灰色过渡区 -->
<rect x="660" y="358" width="210" height="48" fill="#e2e8f0" stroke="none"/>
```

### 类型 E：FSM 状态

画法：
- **一条连续 `<polyline>`**，横跨整个波形宽度
- 状态名标签：位置在线**上方 8px**，font-size=9，font-weight=700
- 状态边界刻度线：从 (y-4) 到 (y+4) 的竖线
- **状态段之间不得有间隙**

```xml
<!-- FSM 状态：单条连续线 -->
<polyline points="220,576 870,576" stroke="#64748b" stroke-width="2" fill="none"/>
<!-- 状态标签在线上方（y = 线_y - 8） -->
<text x="237" y="568" text-anchor="middle" font-size="9" font-weight="700" fill="#64748b">IDLE</text>
<text x="455" y="568" text-anchor="middle" font-size="9" font-weight="700" fill="#64748b">INIT_RESET</text>
<!-- 状态边界刻度线 -->
<line x1="260" y1="572" x2="260" y2="580" stroke="#64748b" stroke-width="1.5"/>
```

### 类型 F：时钟

画法：
- **单条连续 `<polyline>`**——全宽方波
- 颜色：`#94a3b8`，stroke-width：1.5

```xml
<polyline points="220,86 270,86 270,114 300,114 300,86 330,86 ..."
     stroke="#94a3b8" stroke-width="1.5" fill="none"/>
```

## HIGH/LOW 坐标规范（强制）

对于每一个单比特信号：
```
中心 y = 信号行基线
LOW  (0) y = 中心_y + 10   （SVG 坐标中在中心下方 = 较大的 y）
HIGH (1) y = 中心_y - 10   （SVG 坐标中在中心上方 = 较小的 y）
```

**自检规则**：默认值为 0 的信号，其第一个 y 坐标必须 = 中心_y + 10（LOW）。
默认值为 1 的信号，其第一个 y 坐标必须 = 中心_y - 10（HIGH）。

## 时序标注要求

每张时序图必须包含：

1. **脉冲宽度标注**：同时标注物理时间和周期数
   - `init_spine_reset_time = 20ms（@400MHz = 8,000,000 周期）`
   - `tm_redump_width = 7.5ns（@400MHz = 3 周期）`

2. **Setup/Hold 标注**：含最小值和周期分数
   - `setup ≥ 1ns（@400MHz = 0.4 周期）`
   - `hold ≥ 3ns（@400MHz = 1.2 周期）`

3. **寄存器默认值**：在图底部注释行中标出
   - `默认值：init_spine_reset_time=0x7A11FF(20ms), dumpready_timeout=0xC3500(1ms)`

4. **关键时间点说明**：波形下方解释每个 T 标记

## 时序图验证检查清单

导出前逐项验证：

```
□ 每个信号在所有 T 标记处的事件表中都有状态
□ 默认值与接口/寄存器文档一致
□ 默认=0 的信号从 LOW（中心_y + 10）起始
□ 默认=1 的信号从 HIGH（中心_y - 10）起始
□ 总线信号使用填充色带（灰→黄→灰），无交叉斜线，无"X"
□ FSM 状态是一条连续 polyline，无间隙
□ 所有 polyline 是连续的——没有断开的线段
□ 脉冲宽度标注：物理时间 + 工作频率下的周期数
□ Setup/hold 时间包含周期数等效值
□ 信号间时序关系与规格文档的操作序列一致
□ 中间状态已保留——没有跳过
□ 信号位宽与接口文档一致
```

# SVG 导出约束

## qlmanage 方形缩略图问题

`qlmanage -t` 始终生成方形缩略图（如 2800×2800）。如果 SVG 的 viewBox 宽大于高，右侧部分在输出中会被**裁剪**。

**强制要求**：所有用于 qlmanage 导出的 SVG 必须具有方形 viewBox（宽 = 高），且内容填满整个方形。

```
✓ viewBox="0 0 900 900"   （方形）
✓ viewBox="0 0 1060 1060" （方形）
✗ viewBox="0 0 1600 600"  （宽幅——右侧会被裁剪）
```

如何使图表为方形：
- 扩大行间垂直间距
- 在底部添加细节区域（信号表、图例、注释）
- 不要添加空白填充——空白区域会导致裁剪失败

**例外**：用户提供的参考 PDF。`qlmanage` 可以正确处理任意宽高比的 PDF。如有参考 PDF，直接用作 PNG 源。

## 导出脚本

使用 `scripts/export_diagram.py`：
```bash
python3 export_diagram.py <input.html> <output.png>
```

或等效的内联代码：
```python
import re, subprocess
from PIL import Image
import numpy as np

# 从 HTML 中提取 SVG，用 qlmanage 渲染，裁剪到内容
subprocess.run(['qlmanage', '-t', '-s', '2800', '-o', '/tmp', svg_path], capture_output=True)
img = Image.open(thumb)
arr = np.array(img)
gray = np.mean(arr[:,:,:3], axis=2)
cm = (gray < 245) | (gray > 252)
rows, cols = np.any(cm, axis=1), np.any(cm, axis=0)
# 12px 内边距裁剪，RGBA 需合成到 #fafbfc 背景上
```

# 架构图规范

## 箭头方向规则

**箭头必须始终从源头指向目的端。**

### 反馈线（虚线）

反馈 = 信号从下游模块回传到上游模块。

```xml
<!-- 反馈：Timer → FSM（cnt_done）。Timer 在 x=680，FSM 在 x=520。
     箭头必须指向左（朝向 FSM，即目的端）。 -->

<!-- 从 Timer 到 FSM 的虚线路径（从右到左） -->
<path d="M 680 180 L 635 180" stroke="#cbd5e1" stroke-width="1.2"
      stroke-dasharray="6 4" fill="none"/>

<!-- 末端的实线 marker 段：从右到左。
     x1 > x2 表示方向向左 → 箭头指向左 ✓ -->
<line x1="635" y1="180" x2="630" y2="180" stroke="#cbd5e1"
      stroke-width="1.2" marker-end="url(#arr-status)"/>
```

### 反馈箭头自检

对每条带 marker-end 段的虚线：
```
□ marker 段 x1→x2 方向与信号流向一致
□ x1 > x2 → 箭头指向左（从右到左流向）
□ x1 < x2 → 箭头指向右（从左到右流向）
□ 对竖直线段，y1→y2 方向与信号流向一致
```

### 常见错误——不要这样做：
```xml
<!-- 错误：箭头指向右（回到 Timer）而不是指向左（朝向 FSM） -->
<path d="M 680 180 L 630 180" stroke="#cbd5e1" stroke-width="1.2"
      stroke-dasharray="6 4" fill="none"/>
<line x1="630" y1="180" x2="635" y2="180" ... marker-end="url(#arr-status)"/>
<!-- x1=630, x2=635 → 方向向右 → 箭头指向右 → 错误 -->
```

### 标准线型

| 类型 | 描边色 | 线宽 | 虚线 | Marker 填充 |
|------|--------|------|------|------------|
| 地址/控制 | `#334155` | 2.5 | 无 | `#334155` |
| 写控制 | `#3b82f6` | 1.5 | 无 | `#3b82f6` |
| 读控制 | `#d97706` | 1.5 | 无 | `#d97706` |
| 状态 | `#94a3b8` | 1.5 | 无 | `#94a3b8` |
| 反馈（虚线） | `#cbd5e1` | 1.2 | `6 4` | `#94a3b8` |
| 错误路径 | `#dc2626` | 2 | 无 | `#dc2626` |
| 等待循环 | `#94a3b8` | 1.6 | 无 | `#94a3b8` |

### SVG 规则（强制）
- 背景：`<rect width="100%" height="100%" fill="#fafbfc"/>`
- **每一条用作线的 `<path>`**：必须有 `fill="none"`
- **Markers**：用 `<polygon>` 而非 `<path>`
- **禁用 CSS 变量**——使用显式 hex（`#172033` 而非 `var(--fg)`）
- **禁用 `fill-opacity`**——使用显式浅色
- **`orient="auto"`**（不用 `auto-start-reverse`）
- **`&&` → `&amp;&amp;`**（XML 解析前）
- **不用 `sips`**——markers 无法渲染

### 常见陷阱（所有图表）
1. ❌ `<path>` 没有 `fill="none"` → 渲染为纯黑块
2. ❌ `fill-opacity` 或 CSS 变量 → 部分渲染器变黑
3. ❌ `<path>` 在 `<marker>` 内 → 用 `<polygon>`
4. ❌ 虚线反馈箭头指向源头（而非目的端）
5. ❌ 宽幅 SVG 用 qlmanage → 右侧裁剪 → 用方形 viewBox
6. ❌ 总线画成单线 → 用填充色带（灰→黄→灰）
7. ❌ FSM 状态画成分段 → 单条 polyline
8. ❌ 总线过渡区画交叉斜线或"X" → 纯灰填充
9. ❌ 文字覆盖路径线 → 调整间距
10. ❌ 自循环箭头在节点 y 范围之外
11. ❌ 信号位宽未经接口文档确认就猜测

# 文档标准

## 章节编号
所有标题使用编号格式：`1 封面`、`2 修订记录`、`3 概述`、`3.1 功能描述`，等等。

## 端口表
顶层端口表必须有 5 列：**信号名 | 方向 | 位宽 | 默认值 | 描述**
默认值来自接口描述文档。时钟/复位等无意义默认值的信号用"NA"。

## 修订记录
每个生成的版本都在修订记录表中占一行。保留所有历史记录——不删除旧条目。

## 写作风格
- 平实直接的语言。不用"旨在"、"此外"、"确保"、"扮演关键角色"、"核心"、"关键"
- 用"是/有/做"代替"充当/扮演/服务于"
- 段落简短，一个段落一个想法。不用 em dash。
- 不用模糊的归因或填充短语

## 格式（python-docx）
- 字体：Times New Roman（正文），黑体（标题）
- 表格：表头 `#D9D9D9`，`Table Grid` 样式
- 代码：Courier New 6-7pt，1.0 行距
- 页面：A4（21cm×29.7cm），2cm 页边距
- 图表：PNG 嵌入宽度 5.2-5.8 英寸

# 文档结构

1. **封面**——标题、版本、日期、状态
2. **修订记录**——完整版本表
3. **概述**——用途、设计参数、关键决策
4. **顶层模块**——框图、层次表、端口表（含默认值）、例化模板
5. **模块详细设计**——每个 L1 模块：描述、接口、关键 RTL
6. **FSM 设计**——状态编码、状态转移图、转移条件（全部，含等待循环和 OR 条件）、核心 RTL
7. **时序图**——见时序图规范章节
8. **集成指南**——编码顺序、SDC 约束、验证项
9. **附录**——时序检查清单、参考文献

# 工作流程（完整流水线）

```
1. 材料收集
   ├── 阅读所有提供的文档（规格、寄存器文件、接口文件）
   ├── 检查缺失文档 → 立即提示用户
   └── 提取所有参数（信号、默认值、时序、状态）

2. 设计阶段
   ├── 为每个时序场景构建事件表
   ├── 设计 FSM 状态/转移、模块层次
   └── 按类型（A/B/C/D/E/F）分类每个信号

3. 图表创建
   ├── 创建 SVG HTML 文件（方形 viewBox）
   ├── 应用按信号类型的画法规则
   ├── 添加标注（时间 + 周期数 + 寄存器值）
   ├── 执行验证检查清单
   └── 获取用户预览批准

4. 导出
   ├── 通过 qlmanage + PIL 裁剪导出 PNG
   └── 验证宽高比 ≈ 1.0

5. 文档生成
   ├── 构建带编号章节的 .docx
   ├── 包含带默认值的端口表
   ├── 包含完整修订记录
   └── 打开供用户审阅
```
